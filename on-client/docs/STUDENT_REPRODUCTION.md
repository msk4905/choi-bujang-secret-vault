## 3. 재현 절차

원래 작업 폴더와 기록은 건드리지 않고, 같은 상위 폴더에 새 빈 폴더 `repro22`를 만들어 진행했습니다. 아래 명령의 폴더 이름은 예시이며 PC마다 위치가 다릅니다.

1. 원래 폴더 보존 확인: 두 폴더(`main` 작업 폴더, 재현 대상 브랜치 작업 폴더)에서 `git status --short`가 비어 있음. [학생 진술]
2. 새 빈 폴더 확인: `Test-Path .\repro22`가 `False`. [학생 진술]
3. 커밋 받기:
   ```powershell
   git clone --branch submit-oncli-21 --single-branch https://github.com/msk4905/choi-bujang-secret-vault.git repro22
   cd repro22
   git rev-parse HEAD
   ```
   `git rev-parse HEAD`가 T와 같음을 확인. 폴더에는 `.git`, `.gitignore`, `on-client`만 있음. [학생 진술]
4. 런타임 확인: `node --version`이 `v24.19.0`. `on-client` 안에 `.env`와 `node_modules`가 없음을 `Test-Path`로 확인(둘 다 `False`). 기존 폴더의 설정·인증 파일은 복사하지 않음. [학생 진술]
5. 실행: `on-client` 폴더에서 아래 명령.
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Demo
   ```
6. 브라우저에서 `http://127.0.0.1:5189/` 확인.
7. 종료와 재실행: `Ctrl+C`로 종료 → 브라우저에서 `ERR_CONNECTION_REFUSED` 확인 → 같은 명령으로 재실행 → 화면 다시 표시. [학생 진술]
8. 종료 후 `git status --short`가 비어 있음(실행 중 추적되는 파일이 바뀌거나 새 파일이 생기지 않음). [학생 진술]

## 6. 데이터 보존·백업·복원 계획

### 6.1 보존해야 하는 학생 데이터

| 종류 | 위치 | 비고 |
|---|---|---|
| 학생 구현 코드 | `on-client/student/extension.mjs` | Git으로 보존 |
| 학생 문서 | `on-client/docs/STUDENT_RUNBOOK.md`, `on-client/docs/STUDENT_REPRODUCTION.md` | Git으로 보존 |
| 제공 코드·문서 | `on-client/` 나머지 | 시작 틀 0.2.11. 고치지 않았음 |
| 1~12단계 파일 | 프로젝트 최상위 폴더의 `main` 브랜치 | 지우거나 덮어쓰지 않음 |

### 6.2 앱이 자체적으로 저장하는 데이터

- 앱 서버는 프로젝트 폴더에 파일을 쓰지 않습니다. [원문 확인] `src/`·`vendor/`·`student/`·`public/`에서 `writeFile` 등 파일 쓰기 호출을 찾지 못했고, 파일 사용은 읽기뿐임. [학생 진술] 새 폴더에서 실행·종료·재실행한 뒤 `git status --short`가 비어 있음.
- 화면의 판정·조회 결과·기록은 서버를 다시 켜거나 브라우저를 새로고침하면 다시 불러오며, 이전 결과를 파일로 남기지 않습니다. [학생 진술] 재실행 뒤 화면이 새로 시작됨.
- 운영자가 별도 설정 파일을 줄 때만 쓰이는 저장소 두 곳이 있으며, 학생 실행에서는 쓰지 않았습니다. [원문 확인] `src/connection/native-context.mjs`, `src/ai/credential-vault.mjs`(운영자가 구성한 외부 호스트 프로그램에 맡겨 보관), `src/actions/store.mjs`(운영자가 주는 기존 SQLite DB에 조치 기록을 추가). 이 보관 폴더와 DB는 운영자가 관리하며 이 저장소에 넣지 않습니다. 사용하지 않았으므로 동작은 [미확인].
- 실제 설정 파일(`.env`, `.env.*`)과 `node_modules/` 등은 `.gitignore`가 제외하며, 값이 없는 설정 예시 `.env.example`만 예외(`!.env.example`)로 추적합니다. 문서와 커밋에 실제 값을 적지 않습니다. [원문 확인] `.gitignore`, `on-client/.env.example`

### 6.3 백업

- 코드·문서는 `git push`로 원격 저장소(GitHub)에 올립니다.
- 되돌리기가 필요한 기록 변경(커밋 합치기, 강제 푸시) 전에는 현재 브랜치의 복사본 브랜치를 만들어 원격에 올립니다. 21단계에서 `backup-21-before-amend`, `fix-21-doc`로 했습니다. [학생 진술]
- 제출용 브랜치(`submit-oncli-21`)는 `on-client`와 `.gitignore`만 담습니다. 원래 작업 브랜치는 건드리지 않습니다.

### 6.4 복원

- 코드·문서 복원: 새 빈 폴더에서 `git clone --branch <브랜치> --single-branch <저장소 URL> <새 폴더>` 후 해당 폴더의 `on-client`에서 실행. 이 절차로 `submit-oncli-21`을 복원해 실행한 것은 확인했습니다. [학생 진술] `main`과 백업 브랜치의 복원은 같은 방법이지만 시험하지 않았습니다. [미확인]
- 운영자 보관 데이터(연결 자격, 조치 기록 DB): 이 저장소로는 복원할 수 없습니다. 운영자의 절차를 따라야 하며 이 문서는 그 절차를 확인하지 못했습니다. [미확인]

### 6.5 제한

- 백업은 GitHub 계정과 저장소에 의존합니다. 원격 저장소나 브랜치를 지우면 복구할 수 없습니다.
- 커밋하지 않은 변경은 백업되지 않습니다.
- 앱 화면의 실시간 상태(판정·조회 결과)는 보존 대상이 아닙니다. 다시 실행하면 새로 조회합니다.
- 이 계획은 Windows와 PowerShell에서만 확인했습니다. 다른 환경은 [미확인].

## 7. 이동 가능한 구성

- 다른 환경에서 필요한 파일은 `on-client` 폴더 전체입니다. 설치 절차는 Node.js 24.19.0 준비(`package.json`의 `engines.node`가 이 값으로 고정됨) 후 `on-client` 폴더에서 실행 명령 한 줄입니다. 외부 패키지 설치는 없습니다.
- 설정 예시는 `on-client/.env.example`(저장소에 포함됨)이며 실제 값이 없는 설정(포트, 어댑터 경로, 허용 패키지 목록 비어 있음)만 있습니다. 이 문서의 명령과 설명은 특정 PC의 절대 경로나 인증 값에 의존하지 않습니다.
- 실제 시스템(기존 접속·XDR 엔진)·AI 연결은 운영자가 따로 주는 설정 파일로만 켭니다. 이 연결을 새 환경에서 재현한 것은 없습니다. [미확인]
